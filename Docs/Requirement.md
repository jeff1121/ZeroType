# 角色
你是一名熟悉 flutter 的開發者

# 任務
我現在想開發一個跨 Mac (Only M-Chips) 與 Windows 的系統列常駐應用程式，目的是為了讓使用者透過快捷鍵呼叫並串接 AI 模型，以達到語音辨識與修飾內容，並自動輸入到游標位置的目的。

# UI/UX 需求
使用者安裝完應用程式，開啟後會要求必要的系統權限（麥克風、輔助使用/無障礙權限以模擬鍵盤貼上）。權限允許後進入主畫面，主畫面左側欄會有如下選項與功能：

- 模型設定
    - 選擇之後，右側會呈現兩個可以收合的 Section，一個是「語音辨識」，另外一個則是「AI 精修」。
    - 針對語音辨識必須加上 red mark 表示為必填。
    - 點開來之後會提供一個 provider list 以供選擇（包含對應的 API Key 輸入框，API Key 需安全儲存）。
    - 語音辨識目前提供的選項有 OpenAI (例如呼叫 Transcribe 模型)。
    - AI 精修目前提供的選項有 Gemini。
    - 各自點了之後又會有模型列表。我希望針對這些設定檔，可以被抽成一份共用的 txt（或 JSON）當中，讓我未來可以針對這些選項去手動新增或修改。

- 字典檔
    - 一個輸入框，輸入完之後右邊有個加入的按鈕，或是可以按下 Enter 直接加入。
    - 輸入框底下會有一個列表，列表內會出現歷史加入過字典檔的字詞，依照 alphabet order 排序。
    - 實際上的編輯就是直接修改 txt 檔案。
    - **用途說明**：字典檔的內容會在發送 API 時，作為提示詞的一部分（提供給語音辨識 Prompt 或 AI 精修 System Prompt），以提高專有名詞的準確度。

- 提示詞修改
    - 針對語音辨識，會有一個系統提示詞區塊，裡面會放目前預設，你先寫 "這是預設提示詞就好"。
    - 針對 AI 精修，會有一個系統提示詞區塊，裡面會放目前預設，你先寫 "這是預設提示詞就好"。

- 設定
    - 開機啟動 (Launch on startup)
    - 設定啟動快捷鍵 (Global Hotkey)
    - 應用程式行為：關閉主視窗時縮小到系統列 (System Tray/Menu Bar) 常駐。

## 操作流程

1. **觸發錄音**：當使用者在任何應用程式中按下設定的快捷鍵之後，會在螢幕的中間下方浮現一個麥克風小圖示與狀態視窗，並開始存取麥克風錄音。
2. **錄音中**：一旦使用者開始講話，圖示內會出現聲音波形；若要取消錄音，可按下 `Esc` 鍵中斷。
3. **結束錄音**：當使用者說完話，再次按下相同的快捷鍵結束錄音。
4. **語音辨識 (Loading 狀態)**：
   - 浮動視窗轉為「處理中」或「辨識中」的動畫提示。
   - 將錄音檔（暫存於系統暫存資料夾）送往語音辨識所選擇的 Provider API 去進行辨識。
   - 辨識完成後取得文字結果，並自動刪除本機暫存音檔。
5. **AI 精修 (可選)**：
   - 系統會檢查使用者有沒有設定 AI 精修。
   - 如果有設定，則呼叫選定的 AI 精修 API，把語音稿當作 User Prompt 傳入；System Prompt 則組合「提示詞修改」中的預設提示詞與「字典檔」內容。
   - 浮動視窗轉為「AI 精修中」的提示狀態。
6. **自動輸出**：
   - 無論是否有經過 AI 精修，當最終文字結果準備好後，自動將文字複製到系統剪貼簿。
   - 系統偵測使用者目前的游標所在位置，模擬鍵盤動作（如 `Cmd+V` 或 `Ctrl+V`）把文字全部貼上。
   - 貼上完成後，自動隱藏/關閉螢幕中間下方的浮動圖示。
7. **例外處理**：
   - 若過程中有 API 錯誤（如連線失敗、API Key 無效），浮動視窗需顯示紅色錯誤提示（例如 "辨識失敗，請檢查網路或 API Key"）約 3 秒後再消失。

# 現況同步註記（Reconciliation Note）

> 以上為原始 PRD 願景，保留作歷史紀錄。以下依目前原始碼描述已存在的行為，不把未實作的原始需求當成交付內容。

- **無獨立「AI 精修」階段**：目前僅有語音辨識流程，未提供獨立的 Gemini 文字精修 Section（字典檔仍會併入語音辨識 Prompt）。
- **憑證儲存**：API Key 與各項設定存於 `SharedPreferences`（非安全儲存），非原規劃的 `flutter_secure_storage`。
- **Provider、通道與憑證**：OpenAI／Gemini 提供官方與 Proxy 通道，Azure 僅官方。Gemini 官方可用 **API Key** 或 **Antigravity OAuth**，其他通道使用 API Key；獨立 Gemini OAuth 入口已於 v1.2.0 移除。Antigravity 可以由 App 發起登入或引用本機既有候選來源；不應描述成已提供固定帳號選擇器。
- **即時模型目錄**：依使用者 2026-10-14 回饋，選單只顯示完整原始 ID 並按 ID 排序，移除可能混淆版本的供應商顯示名稱。目錄來源、合法空結果與查詢失敗分開；失敗先使用同來源記憶體快取，再使用適合該通道的內建目錄，保留已選 ID 且不自動改選。
- **模型選單尺寸**：收合欄位外框高度縮短 40%，文字字級保留；展開選項的 64 基準列高及能力提示不縮短，仍隨系統文字縮放調整。展開選單高度限制為視窗的 60%、最多 420；長 ID 截短顯示並提供完整 ID 的 tooltip。選單、收合欄位與已排除項目均不重新顯示供應商回傳的模型名稱；Provider 按鈕仍顯示供應商名稱。
- **語音能力**：Antigravity 依目前錄音請求的 `audio/mp4` 判斷支援／不支援／未確認；缺 metadata 不會排除模型。明確不支援者不提供新選擇，既有選取保留並警示，目錄不成為轉寫前置閘門。Proxy 自訂別名與 Azure 手動部署保持相容。
- **更新與來源隔離**：目錄以 Provider、通道、endpoint 與憑證情境隔離；同來源更新保留目前清單，連點共用請求，晚到結果及舊選單不能覆寫新來源或儲存已過期候選。選模型僅保存原始 ID，不重新查授權或目錄；目錄快取只留在記憶體。
- **Gemini 逐字稿提取**：第一個候選的多個可見文字片段依序合併，略過 `thought: true`；帶 `thoughtSignature` 的可見文字仍保留。封鎖、輸出截斷、只有思考或沒有可讀文字使用明確錯誤，不把部分結果貼上。這是回應解析修補，未改提示詞、音訊 payload 或原始 model ID，也不表示每個模型都完成實際轉寫測試。
- **錄音與歷史**：目前錄音為 16 kHz AAC/M4A。成功取得非空文字後，音檔移到歷史目錄並保存文字、模型、通道及用量；並非原 PRD 所述「辨識完成即刪除所有音檔」。正常回應的空文字走錯誤流程並清除該暫存音檔，不寫歷史；保留天數與刪除功能另管理已保存紀錄。
- **提示詞**：優先使用本機自訂的語音提示詞，否則使用 bundled `SpeechToText.prompt`；送出前附加自訂字典。沒有獨立 AI 精修提示詞或第二次精修請求。
- **平台操作邊界**：macOS 使用原生浮動 overlay；Windows 的可見 overlay 由 Flutter 繪製於應用視窗內。主視窗關閉會隱藏到系統列，退出由系統列功能執行。平台模擬與 Windows CI 編譯不能代替實機人工操作驗收。
- **Azure OpenAI Whisper**：第三個語音辨識 Provider（僅官方通道，使用者填 Endpoint / API Key / API Version；model id 為部署名稱）。詳見 `Docs/Tasks.md` 第九節。
